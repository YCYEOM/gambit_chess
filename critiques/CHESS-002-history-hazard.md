# CHESS-002 critic finding

## [해결됨] `render()` 가 `game.history()` 를 호출해 전투 결과를 되돌렸다

- **심각도**: high (게임 규칙이 조용히 무효화됨)
- **확신도**: 확정 — 재현 및 수정 후 재검증 완료
- **위치**: `src/main.ts` (수정 전 `render()`), `src/duel.ts:20-27` (경고 주석)

### 무엇이 잘못됐나

`playMove()` 는 공격이 실패하면 `game.remove()` + `game.put()` 으로 반상을 고친다.
그런데 `chess.js` 의 `history()` 는 읽기 API 처럼 보이지만 실제로는 **초기 위치부터
모든 수를 다시 재생**해 SAN 을 만든다. 이 과정에서 현재 반상이 통째로 덮어써지고,
전투로 무산됐던 공격이 "성공" 상태로 되살아난다.

`render()` 가 기보 표시와 직전 수 강조를 위해 `history()` 를 두 번 호출하고 있었으므로,
화면을 그리는 것만으로 게임 규칙이 무효화됐다.

### 검증 방법

```
1. 공격 실패 상태를 만든다 → game.get('e5') === 흑 폰
2. game.history() 를 호출한다
3. game.get('e5') === 백 나이트  ← 되살아남
```

`src/duel.test.ts` 의 "history() 는 반상 수정을 되돌린다" 테스트가 이 동작을 고정한다.

### 왜 단위 테스트를 통과했나

`duel.test.ts` 는 `playMove()` 직후의 반상만 확인했다. `history()` 를 호출하는 것은
UI 뿐이었고, 그 경로에는 테스트가 없었다. **실제 화면에서 한 판 두어 보지 않았으면
발견하지 못했다.**

### 조치

`main.ts` 가 `{ san, from, to, repelled }` 기보를 직접 쌓고 `history()` 를 전혀 쓰지
않도록 바꿨다. `duel.ts` 에 경고 주석과 이유를 남겼고, 위 테스트로 라이브러리 동작을
고정했다.

### 남은 위험

`isDraw()` 의 3회 동형 반복 판정은 chess.js 내부 이력을 쓰므로 여전히 전투로 뒤집힌
반상을 반영하지 못한다. 반상을 덮어쓰지는 않으므로 규칙 무효화는 아니며,
`README.md` 의 알려진 한계에 기록했다.
