# Gambit Chess

브라우저에서 도는 3D 체스. AI와 1:1로 둔다. 기물은 캐릭터다 — 백은 모험가, 흑은 해골 군단.
모드가 둘이다.

- **결투 모드** (기본) — 기물을 잡을 때 자동으로 먹지 않는다. 두 기물이 실제로 싸우고,
  이긴 쪽이 칸을 차지한다. 공격에 실패하면 공격자가 죽고 수비 기물이 제자리에 남는다.
- **정통 체스** — 보통의 체스.

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # 전투·판정·AI 엔진 테스트
npm run build
```

## 구성

| 파일 | 역할 |
| --- | --- |
| `src/combat.ts` | 전투 판정 (순수 함수, DOM·체스 규칙과 무관) |
| `src/duel.ts` | 전투 결과를 반상에 반영 — chess.js 와 전투 사이의 접합부 |
| `src/ai.ts` | 알파-베타 미니맥스 + 기물 가치/위치 평가 |
| `src/board3d.ts` | three.js 렌더링 — 배역·배율·조명·카메라·전투 연출 |
| `src/main.ts` | 게임 진행, 입력, 상태 표시 |
| `index.html` | 마크업 + 전체 CSS + 색 토큰 |
| `scripts/balance.ts` | 전투 승률표 재계산 |
| `tools/strip-anims.mjs` | 모델에서 쓰는 애니메이션만 남긴다 |

## 캐릭터

[KayKit](https://kaylousberg.com) 의 CC0 팩. 무료분이 모험가 5종·해골 4종뿐이라 6역을
채우려면 변주가 필요한데, 방법이 진영마다 다르다 — 모험가는 무기·투구가 모델 안에 별도
메시로 들어 있어 켜고 끄면 되고, 해골은 무기가 별도 파일이라 `handslot` 본에 붙인다.

| 기물 | 백 (산 자) | 흑 (죽은 자) |
| --- | --- | --- |
| 폰 | 병졸 | 해골 잡졸 |
| 나이트 | 도적 · 단검 둘 | 해골 도적 · 검 |
| 비숍 | 두건 사수 · 석궁 | 해골 사수 · 두건 · 석궁 |
| 룩 | 야만전사 · 양손도끼 | 해골 전사 · 도끼 |
| 퀸 | 마법사 · 지팡이 | 해골 마법사 · 지팡이 |
| 킹 | 기사 · 검·방패·투구 | 해골 군주 · 뿔투구·검·방패 |

원본 모델은 애니메이션이 76~95개라 합쳐서 35.6MB 였다. `node tools/strip-anims.mjs` 로
`Idle`·`Attack_1H`·`Attack_2H`·`Hit`·`Death` 다섯만 남겨 4.2MB 로 줄였다. 모델을 다시
받거나 바꾸면 이걸 돌린다.

규칙 판정(캐슬링, 앙파상, 승진, 체크메이트, 무승부)은 `chess.js`가 담당한다.
직접 짜면 엣지 케이스에서 틀린다.

## 전투 규칙

움직인 쪽이 선공하고, 한쪽 HP가 0이 될 때까지 번갈아 때린다. **첫 타격은 기습이라 1.25배**
들어간다. 타격마다 ±50% 변동, 12% 확률로 치명타(×2.5). 공격자 승률:

|        | 폰 | 나이트 | 비숍 | 룩 | 퀸 | 킹 |
| --- | --- | --- | --- | --- | --- | --- |
| **폰**    | 75% | 38% | 38% | 16% | 4% | 11% |
| **나이트** | 93% | 77% | 76% | 47% | 16% | 33% |
| **비숍**   | 94% | 77% | 77% | 46% | 17% | 33% |
| **룩**    | 99% | 92% | 92% | 78% | 40% | 66% |
| **퀸**    | 100% | 99% | 99% | 94% | 78% | 90% |
| **킹**    | 100% | 95% | 95% | 86% | 55% | 77% |

같은 기물끼리 75~78%인 것이 선공 + 기습의 이점이다. **먼저 치는 쪽이 확실히 유리하되,
가치가 높은 기물을 치는 것은 여전히 불리하다** — 나이트로 룩을 치면 47%, 폰으로 퀸을 치면
4%다. 기습 보정이 없으면 각각 38%, 2% 이고 동급끼리도 69% 라, 체력이 이어지는 상황에서
공격이 손해가 됐다. 수치를 바꾸면 `npx vite-node scripts/balance.ts`로 표를 다시 뽑는다.

AI도 승률을 본다. 잡기를 공짜로 여기지 않고 `(1-승률) × (내 기물 + 상대 기물)` 만큼
할인해서, **빈사 상태로 덤비지 않고 다친 적을 노린다.** 승률은 표로 박아 두지 않고 그때그때
200번 굴려 기억해 둔다 (`winChance`) — 밸런스 상수를 바꿔도 저절로 따라온다.

### 체력은 이어진다

기물은 **깎인 체력을 그대로 들고 다닌다.** 한 번 크게 다친 기물은 다음 전투에서 불리하고,
그래서 "약해진 기물을 노린다"와 "물러나서 쉰다"가 둘 다 성립한다.

- 다친 기물은 머리 위에 체력 바가 뜬다. 만피면 표시하지 않는다.
- 한 턴이 지날 때마다 최대 체력의 8%씩 회복한다 (최소 1). **방금 움직인 기물은 빠진다** —
  싸우거나 행군한 기물은 쉰 게 아니다.
- 승진하면 새 몸이라 만피로 시작한다.
- 정통 체스 모드에는 적용되지 않는다.

### 킹은 죽어야 진다 (결투 모드)

잡기가 확률이면 "겨눠진 칸" 은 죽는 칸이 아니라 **죽을 수도 있는 칸**이다. 그래서 결투
모드에서는 규칙이 이렇게 풀린다.

- **빨간 X 는 금지가 아니라 경고다.** 킹이 겨눠진 칸으로 나서는 것도, 핀에 걸린 기물을
  그냥 움직이는 것도 할 수 있다. 표시를 보고도 가겠다면 간다.
- **체크·체크메이트는 경고다.** 몰렸어도 둘 수가 하나라도 남아 있으면 판은 안 끝난다.
- **킹은 실제로 전투에서 져야 죽는다.** 노출된 것만으로는 지지 않는다 — 상대가 와서
  이겨야 한다. 반대로 킹이 버티면 잡으러 온 쪽이 죽는다.
- 킹이 직접 잡으러 갔다가 지면 그 자리에서 패배한다 (그건 실제로 죽은 것이다).
- **이 자유는 사람만 누린다.** AI 는 정통 체스 규칙 그대로 둔다 — 몰아붙여 체크메이트를
  만들면 거기서 끝난다. AI 도 빠져나가면 이긴 것이 이긴 게 아니다.
- 완전히 갇혀서 둘 수가 하나도 없으면 그때 패배다. 스테일메이트도 같다 — **몰아붙인 쪽의
  승리**로 친다. "이겼는데 무승부" 는 아케이드로 맞지 않는다.

**정통 체스 모드는 하나도 바뀌지 않는다.** 전투도, 위험을 무릅쓴 수도, 아이템도, 연승 런도
없다. 체크메이트는 체크메이트고 스테일메이트는 무승부다.

전투에 져서 무산된 수는 기보에 `✗`로 표시된다. SAN 표기(`Nxe5`)만 보면 잡은 것처럼 보이기
때문이다.

## 아이템

**6수마다** 빈 칸에 아이템이 하나 나타난다 (반상에 최대 2개). 기물이 그 칸으로 가면 줍는다.
아이템은 빈 칸에만 놓이므로 **잡는 수로는 절대 줍지 못한다** — 잡으러 갈지 아이템을 주우러
갈지가 매 수의 선택이 된다.

| 아이템 | 효과 |
| --- | --- |
| 재행동 | 즉시 한 번 더 둔다 |
| 예리함 | 그 기물 치명타 확률 +15%p (영구) |
| 분노 | 그 기물 공격력 +3 (영구) |
| 응급처치 | 그 기물 체력을 만피로 |

효과는 **기물에 붙어 따라다닌다.** 그 기물이 죽으면 함께 사라진다. 승진하면 몸은 새것이
되지만 얻은 능력은 가져간다. 능력을 지닌 기물은 발밑에 보라색 고리가 생긴다.

정통 체스 모드에는 나오지 않는다.

## 직전 수

마지막에 둔 수가 화살표로 남는다 — 어느 기물이 어디서 어디로 갔는지. 전투에 져서 무산된
공격은 빨간 화살표다 (갔다가 죽었다는 뜻).

캐슬링은 두 기물이 한 수에 움직이므로 화살표도 둘이다. 킹은 밝게, 함께 넘어온 룩은 흐리게
그린다 — 룩을 안 그리면 킹이 룩을 뛰어넘은 것처럼 보인다.

## 갈 수 없는 칸

기물을 고르면 갈 수 있는 칸은 초록, **위험하거나 규칙이 막는 칸은 빨강 + X** 로 나온다.
결투 모드에서 빨강은 **경고**라 눌러서 갈 수 있고, 정통 체스에서는 **금지**라 누르면 이유가
상태줄에 뜬다 — 핀에 걸렸는지, 체크를 못 푸는 수인지. 이동 규칙을 다시 짜지 않고 `chess.js` 로 뽑는다: 자기 킹을 잠시 치우면 체크 제약
없는 수가 나오므로, 거기서 합법수를 빼면 남는 것이 막힌 칸이다 (`src/duel.ts`).

## 연승 런

결투 모드에서 **이기면 다음 판으로 이어진다.** 상대 난이도는 고른 그대로이고, 이길 때마다
강화 세 장 중 하나를 골라 내 기물에 붙인다. 지면 거기서 끝이고 최고 연승만 남는다.

### 강화

**기물 종류 전체**에 붙는다 (아이템은 기물 한 개에 붙는다). 종류마다 크기가 다른데, 처음
개수가 곧 강화의 크기이기 때문이다 — 폰 여덟에게 퀸과 같은 값을 주면 폰이 퀸을 이긴다.

| 대상 | 단련 (공격력) | 급소 (치명타) |
| --- | --- | --- |
| 폰 | +1 | +5%p |
| 나이트 · 비숍 · 룩 | +2 | +10%p |
| 퀸 · 킹 | +3 | +15%p |
| 전군 (해금) | +1 | +5%p |

같은 강화를 또 고르면 겹쳐 쌓인다. 강화된 기물은 발밑에 보라색 고리가 생긴다.

폰이 끝 줄에 닿으면 **무엇으로 승진할지 고른다** (퀸·룩·비숍·나이트). 카드에는 기물 이름과
역 이름을 함께 적는다 — 반상에서 보이는 것은 "마법사" 지만 고르는 것은 "퀸" 이라, 둘 중
하나만 있으면 무엇을 고르는지 알 수 없다. 어떻게 움직이는지도 한 줄 붙고, 결투 모드에서는
체력·공격력도 나온다 — 퀸이 언제나 정답은 아니다. 승진하면 강화도 새 종류를
따라간다: 폰 몫을 내려놓고 그 종류의 강화를 받는다. 전군 강화와 아이템으로 얻은 효과는
그대로 따라온다.

### 합성 (해금)

같은 기물 둘을 더 센 기물 하나로 바꾼다. **새 기물은 만들지 않는다** — 기존 여섯 역
안에서만 오가므로 이동 규칙도, 모델도, AI 평가도 그대로다.

폰 2 → 나이트 · 폰 2 → 비숍 · 나이트 2 → 룩 · 비숍 2 → 룩 · 룩 2 → 퀸

재료는 **가장자리부터** 내놓고 (중앙 기물을 없애면 진형이 먼저 무너진다) 그 자리에 새
기물이 선다. 재료가 모자란 합성은 후보에 나오지 않는다. 룩을 둘 다 써 버리면 캐슬링
권리도 함께 사라진다.

### 해금

최고 연승이 열쇠다. 저장은 늘리지 않는다 — 기록 하나에서 파생한다.

| 최고 연승 | 열리는 것 |
| --- | --- |
| 2 | 전군 강화 |
| 4 | 합성 |

**런 사이에 남는 것은 해금뿐이다.** 얻은 강화와 합성은 런이 끝나면 사라진다 — "매번
처음부터"가 이 모드의 긴장이라, 영구 성장 대신 *고를 수 있는 카드*만 늘어난다.

반상 위 줄에 지금 런의 연승·상대 난이도·가진 보상이 뜬다. 최고 연승은 브라우저에 남는다
(`localStorage`, 그 한 줄이 전부다).

정통 체스 모드에는 없다 — 전투가 없으니 보상이 걸 곳도 없다.

## 난이도

여섯 단계. 앞의 넷은 깊이가 아니라 **손떨림**(점수에 섞는 잡음)으로 갈린다. 얕게 봐도
실수는 안 하기 때문에 깊이만 줄여서는 사람 기준의 "쉬움"이 안 나온다.

| 단계 | 어떻게 | 한 수에 걸리는 시간 |
| --- | --- | --- |
| 입문 | 1수 + 손떨림 큼 | 0초 |
| 쉬움 | 1수 + 손떨림 | 0초 |
| 보통 | 2수 + 손떨림 | 0초 |
| 어려움 | 3수 + 손떨림 조금 | ~0.7초 |
| 매우 어려움 | 4수 | ~3초 |
| 최강 | 6초 동안 갈 수 있는 데까지 (5~6수) | ~6초 |

탐색은 정지 탐색(잡기 연쇄가 멎을 때까지 더 본다)과 반복 심화를 쓴다. 시간으로 끊는 이유는
깊이를 하나 올릴 때마다 시간이 서너 배가 되고 그 배수가 국면마다 달라서, 깊이만 정해 두면
어떤 국면에서 몇 초 멈출지 알 수 없기 때문이다.

## 알려진 한계

- **AI는 아이템을 주우러 가지 않는다.** 이미 얻은 능력은 전투 승률 계산에 반영하지만,
  반상의 아이템을 목표로 삼지는 않는다.
- **AI의 체력 판단은 자기 수까지만 정확하다.** 뿌리(실제 반상)에서는 양쪽 체력을 그대로
  쓰지만, 더 깊은 수는 가상의 위치라 만피 기준으로만 본다. 체력 지도가 칸을 키로 하기
  때문에 가상 위치에서 조회하면 엉뚱한 기물의 값이 나온다.
- **WebGL 이 필요하다.** 2D 유니코드 반상은 3D 도입과 함께 버렸다. 렌더러를 둘 유지하면
  기능 하나 고칠 때마다 양쪽을 고쳐야 해서다. WebGL 이 없으면 빈 화면이 나온다.
- **스크린 리더로 반상을 읽을 수 없다.** canvas 하나라 2D 시절보다 나빠졌다.
- **`game.history()` / `game.pgn()`을 호출하면 안 된다.** 초기 위치부터 수를 재생하면서
  현재 반상을 덮어써, 전투로 무산된 공격이 되살아난다. 기보는 `main.ts`가 직접 쌓는다.
  (`src/duel.test.ts`가 이 동작을 고정해 둔다.)
- **3회 동형 반복 무승부**는 chess.js의 내부 이력을 쓰므로 전투로 뒤집힌 반상을 반영하지
  못한다. 실제로 걸릴 일은 드물어 그대로 뒀다.
- **움직인 적 없는 룩을 노린 공격이 무산되면 캐슬링 권리가 사라진다.** 룩은 살아남는데
  chess.js 가 잡힌 것으로 보고 권리를 이미 지운 뒤다. 되살리려면 FEN 을 다시 읽어야 하는데
  그러면 `undo()` 가 깨진다 — 드문 경우라 그대로 뒀다.

## 의도적으로 생략한 것

- **전투 재생 건너뛰기** — 재생이 5초를 넘지 않아 아직 필요 없다. 넣더라도 재생만
  생략하고 판정은 그대로여야 한다.
- **기물 이동 경로 애니메이션** — 지금은 직선으로 미끄러진다. 나이트가 넘어가는 모션이나
  걷는 애니메이션은 넣지 않았다.
- **드래그 앤 드롭** — 클릭 두 번으로 충분.
- **Web Worker** — 탐색이 메인 스레드를 막는다. 최강은 최대 6초 멈춘다.
- **판 사이에 남는 영구 성장** — 보상은 런이 끝나면 사라진다. 남는 것은 최고 연승과
  그것으로 열린 카드뿐이다.
- **새 기물** — 합성은 기존 여섯 역 안에서만 오간다. 새 이동 규칙을 만들지 않는다.
- **AI 의 보상** — 상대는 난이도로만 세진다.
